# 事件时间流处理引擎（Go，本地可运行）

一个零外部依赖、纯内存的事件时间（event-time）流处理引擎。用内存事件源模拟多分区
实时数据流，在**乱序到达、重启恢复、重复投递**三种干扰下，使窗口聚合结论保持
确定且可解释。

- 基于**事件时间**的滚动窗口聚合（sum + count）
- 基于**多分区水位线（watermark）**的窗口触发
- **允许迟到**：窗口触发后，迟到但仍在宽限期内的事件产生版本化修正结果
- **状态快照/恢复**：在任意已提交水位线处重启，结果不重复、不丢失
- **多来源并发注入** + **幂等输出汇**
- 全部内存结构**有界**，长时间运行不会无界增长
- 完整测试：`go test` 覆盖乱序、恢复、重复、并发、内存边界

## 事件时间语义

### 窗口划分

`TumblingWindows` 将事件时间轴划分为固定大小、左闭右开 `[start, end)` 的滚动窗口。
窗口边界用 `UnixNano` 对窗口大小取整（UTC），与事件到达顺序无关，因此同一批事件
无论以何种顺序输入，窗口归属完全一致。

### 水位线与全局水位线

- 每个分区（来源）独立上报分区水位线；
- **全局水位线 = 所有分区水位线的最小值**。尚未上报过水位线的分区视为时间零点，
  会拖住全局水位线——保证慢分区的数据不会被快分区"抢跑"丢弃；
- 全局水位线**只进不退**：分区水位线回退直接返回
  `ErrWatermarkRegression` 拒绝。

### 窗口触发

当全局水位线满足 `watermark >= windowEnd` 时窗口触发，把聚合结果写入输出汇。
每次触发（包括迟到修正触发）分配严格递增的**版本号**。窗口输出按
`(窗口起点, key)` 排序，保证输出与快照字节级确定。

## 迟到策略

设窗口大小 `W`、允许迟到 `L`、当前已提交全局水位线 `wm`：

1. **先去重（只读）**：事件 ID 已见过 → 返回 `ErrDuplicateEvent`，不产生任何影响。
2. **再判迟到**：若 `eventTime + L < wm` → 返回 `ErrLateEventDropped`，
   事件被**明确拒绝**（带原因），不写入去重表、不进入窗口。
3. 否则接受：写入去重表并聚合。若此时窗口已触发过
   （`windowEnd <= wm`，即允许迟到内的迟到事件），立即输出一个**修正版本**，
   由输出汇幂等覆盖旧结果。

> 先查重复再判迟到，是因为去重表的保留切点与"最后一个可能受影响窗口的关闭点"
> 对齐（见下）。仍留在表内的重投事件必然不是超迟到事件，二者语义清晰、互斥。

### 顺序无关性

最终聚合值只取决于"哪些事件被接受"。去重表、迟到判定、窗口聚合都是纯函数式的
状态转移；到达顺序只可能影响中间版本号，不影响最终 `(key, window) -> (sum, count)`。
`TestOutOfOrderDeterminism` 用多种确定性乱序排列验证最终结论一致。

## 快照与恢复

`Engine.Snapshot()` 在**已提交水位线**处导出完整状态：

- 已提交全局水位线、各分区水位线
- 各分区消费偏移 `offset`
- 全部存活窗口的 `(sum, count, version)`
- 去重表、输出汇当前结果

快照以 JSON 存储（`SaveCheckpoint` 先写临时文件再原子 rename）。

恢复（`Restore`）时进行两项校验，失败返回**可区分**的错误：

- 当前引擎的已提交水位线**晚于**快照水位线 →
  `ErrWatermarkRegression`（重启只能回到不超过当前提交点的位置）；
- 输出汇中同一 `(key, window)` 的版本号**新于**快照版本 →
  `ErrSnapshotConflict`（恢复会丢弃已确认的更新输出）。

恢复后从快照中的**分区偏移**继续消费，配合去重表，保证：

- 快照之前已处理的事件重投 → 被去重或迟到策略拦截，**不重复**；
- 快照之后的新事件 → 正常聚合，**不丢失**（见 `TestSourceRunWithRestart`）。

去重淘汰切点为 `wm − L − W`：早于该点的事件不可能再影响任何存活窗口，其重投
必被迟到拒绝；该点之后（含边界）的事件重投必被去重拦截。

## 并发与内存约束

### 并发

- `PartitionedSource` 每个分区一个 goroutine，**分区内严格按 offset 顺序**注入，
  保持同一来源（及同一键）的事件顺序语义；
- 引擎所有公开方法由单一互斥锁串行化。多来源并发下，聚合状态机的每次状态转移
  等价于某种顺序执行，因此最终结果确定（`go test -race` 无告警）。

### 幂等输出汇

输出汇以 `(key, windowStart)` 为主键做版本化 upsert：

- 相同版本（重启后重复触发）→ 忽略；
- 更旧版本 → 忽略；
- 更新版本（迟到修正）→ 覆盖。

因此重复投递同一事件对结果**至多产生一次影响**。

### 内存有界

每次水位线提交都会执行清理：

| 结构 | 清理规则 | 上界 |
|---|---|---|
| 窗口状态 | `windowEnd + L <= wm` 时删除 | 约 `(L+W)/平均事件间隔` |
| 去重表 | 切点 `wm−L−W` 之前淘汰；超 `DedupMaxSize` 时按最老事件时间硬淘汰 | `max(DedupMaxSize, 时间下界内条数)` |
| 输出汇 | 默认 `windowEnd + L <= wm` 时 GC | 与存活窗口同阶 |

`Config.RetainClosedResults=true` 时输出汇保留全部历史结果（等价物化结果表，
随输出基数增长，仅用于演示/测试）。生产中需要永久留存结果时，实现 `Sink`
接口对接外部存储即可，引擎内部状态始终有界。`TestBoundedMemory` 注入 5000 个
事件验证三项结构均稳定在常数规模。

## 错误一览

| 错误 | 含义 |
|---|---|
| `ErrDuplicateEvent` | 重复事件被去重忽略（非致命，结果不受影响） |
| `ErrLateEventDropped` | 超出允许迟到，事件被明确拒绝（非致命） |
| `ErrWatermarkRegression` | 分区水位线回退，或向更旧快照点恢复 |
| `ErrSnapshotConflict` | 快照与当前已确认输出版本冲突 |
| `ErrEngineClosed` | 引擎已关闭 |

## 本地演示脚本说明

`go run ./cmd/engine-demo` 分六个阶段（窗口 10s、允许迟到 5s）：

1. 乱序注入 wm=10 前事件，提交水位线 10，触发第一批窗口；
2. 注入 wm∈(10,20] 事件，提交水位线 20；
3. 允许迟到内修正、重复投递（忽略）、超迟到（明确拒绝）；
4. 在已提交水位线 30 处快照并"崩溃"；
5. 新引擎从快照恢复，整批重放，结论不重复不丢失；
6. 演示对旧快照恢复、水位线回退的明确拒绝。

引擎详细处理日志（`ACCEPT/DUP/DROP/EMIT/CORRECT/WATERMARK`）输出到 stderr，
测试中通过 `Engine.SetLogger` 转发到 `testing.T`。
